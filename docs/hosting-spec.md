## Problem Statement

**October 2026 revision:** Hosted questions use direct interpretation, including vague metrics and same-name players, without confirmation or revision panels. Each clarification by the user is a fresh, complete question and counts toward the ordinary hourly allowance. Obsolete confirmation requests are rejected before admission. The browser renders the model's safe Markdown answer, including any model-written tables, with no separate supporting-results table or checkbox. This supersedes the pending-confirmation and optional-table requirements below; existing operational tables remain for schema compatibility. Controlled Preview retains its fixed supported questions and makes no paid model calls. Local evaluation controls are unchanged.

The owner wants invited people to use the MLB batting question application at a custom subdomain without running Go locally. A public deployment currently exposes unprotected, paid model calls; local confirmation memory and log files do not survive independent hosted instances. Hosting must remain on free service tiers while keeping production OpenAI question usage within a shared $10 monthly allowance.

## Solution

Host the existing Go browser application at **baseball.jamesteuscher.click** on Vercel Hobby. Use invite-only Clerk email OTP, a bundled read-only SQLite season snapshot, and free Neon PostgreSQL for the small amount of shared operational state. Enforce authorization, twenty questions per user per hour, one active request per user, conservative pre-call budget reservations, and a two-minute request deadline on the server.

Deploy successful changes from main automatically after tests pass. Protect preview deployments, use explicitly labelled controlled responses there, and keep production credentials and state separate. Preserve the existing baseball rules, Markdown presentation, loading animation, optional database tables, corrections and independent comparison outcomes.

## Implementation Decisions

- **Runtime and environments:** Keep Go, the OpenAI Go SDK, and the browser interface. Add explicit local, preview and production composition. Honor Vercel’s supplied HTTP port and hosted process requirements. A hosted deployment must never fall back to unauthenticated local behavior because a required setting is absent. Missing production dependencies fail closed. Ordinary local configuration and controlled tests remain available.
- **Snapshot packaging:** Produce or embed a reproducible immutable SQLite snapshot from the corrected export as part of deployment preparation. Read-only query connections and all existing authorization restrictions remain. Private snapshot bytes may be materialized in function-local scratch space, but are never a public asset or a shared writable database. Snapshot import is separate from question execution. Shared operational PostgreSQL does not contain or replace batting statistics.
- **Authentication:** Use Clerk’s free invite-only mode with email OTP and dashboard-managed invitations. Its separately paid Allowlist and user-ban features are not prerequisites. Verify session signatures, issuer and appropriate request/session binding using supported Clerk mechanisms, and verify current approved/active user eligibility for every protected request. Dashboard removal of an existing user must deny subsequent question requests rather than waiting for browser UI state to change. Define and document the free dashboard removal workflow. Never accept a browser-supplied email as authority. Sign-in failures cannot reach the model or expose internal reasons/credentials; sign-out clears displayed results and pending browser context.
- **Operational state:** Use one free Neon PostgreSQL service for persistent confirmations, rate admission, active-request leases, and spending records. Add durable migrations and server-owned interfaces below the existing HTTP boundary. Use transactions and conditional updates or row locks; in-process mutexes are insufficient for hosted admission and accounting. State outages, unknown migration versions and free-quota exhaustion deny protected work. No automatic paid upgrade or second paid state service is introduced.
- **Confirmation ownership:** Persist opaque, fifteen-minute, one-use pending confirmations with the authenticated user, original question, resolved intent, private player distinction and question-admission identity. Consume them atomically only for the matching authenticated user and request. Mismatched, expired, forged and replayed tokens execute no generated SQL. A revision can produce a replacement confirmation without creating conversation memory or duplicating hourly question charges. Expired pending content is removed or made inaccessible and eligible for cleanup.
- **Question admission:** Enforce twenty newly admitted questions in a rolling sixty-minute window per stable authenticated user identity, across instances. Resuming or revising a valid pending question reuses its admission. Invalid credentials and forged/replayed confirmations do not create an admission. Concurrent requests for one user acquire a single bounded lease; expired leases recover after process failure and an older request cannot release a newer lease. Count admitted questions that ultimately fail normally; do not grant unlimited retries after a provider error. Return friendly rate/concurrency errors and the appropriate retry context without exposing internal records.
- **Request deadline:** Apply one 120-second deadline to the complete hosted question request, including model planning, correction, database work and summaries. Each SQL execution still has its existing ten-second ceiling, and there remains at most one correction per strategy. User think-time between a clarification and confirmation is governed by the separate fifteen-minute confirmation lifetime. Preserve a strategy outcome completed before another strategy is cancelled. All controls use the same parent cancellation/deadline; cleanup and uncertain accounting must not extend the paid-work deadline.
- **Monthly allowance:** Maintain one production allowance of exactly $10 USD per UTC calendar month for this application’s OpenAI question calls, with no administrator override in this version. The next period starts at 00:00 UTC on the first. Reservations and settled usage belong to the month in which the call was admitted, including when it completes after midnight. Use integer money units, upward rounding and atomic durable transactions. Every planning, correction and answer call in each strategy must commit an adequate reservation before contacting the provider. The invariant is settled charges plus outstanding reservations at or below the monthly allowance.
- **Conservative cost bounds:** Bound the complete provider input and generated output, including instructions, schemas, correction context, answer tables and hidden/reasoning output where billed. Use an explicitly validated model/pricing profile, supported service tier and processing assumptions; reserve at the highest applicable input category rather than assuming a cache discount. Configure output-token limits and a validated conservative input-token upper bound or verified complete-payload count. Unknown prices, tiers, bounds or usage cannot authorize a paid call. Keep SDK retries and paid fallbacks disabled unless individually reserved; this version introduces neither tools with extra charges nor alternate billing providers.
- **Reservation disposition:** Settle no lower than a trustworthy upper bound on returned billable usage at the validated rates. Keep the full reservation on timeouts, interrupted streams, ambiguous network failures, missing/untrusted usage, or an uncertain settlement operation. Release funds only when it is provable they were not consumed. Never silently refund uncertain billed work or release it simply because a lease expires. Conservative accounting can pause questions before the provider invoice reaches $10. Use a dedicated production OpenAI project/key and scope the allowance to this app; unrelated key usage, taxes, platform fees and future provider price changes are not an account-level guarantee.
- **Model and strategies:** Preserve administrator model and strategy selection. The inspected local model is gpt-6.1-sol, with schema prompting as default and comparison disabled; deployment must not silently substitute a different model. Production enablement requires its verified pricing/token/tier assumptions, and switching a model requires an appropriate validated pricing profile. Optional comparison stays within the same allowance and 120-second deadline. When no funds are available, return a natural-language error with the UTC reset time and preserve the previous browser answer.
- **Hosted diagnostics:** Send safe, private error diagnostics to the hosting runtime’s administrator-only logs, with bounded stage/error-class/request identifiers sufficient to diagnose failures. Do not dump full provider payloads, user questions, generated SQL, tables or answers. Scrub credentials and sensitive connection/authentication material. Full evaluation histories are not recorded.
- **Previews:** Non-production deployments use controlled responses and a visible preview notice. Known fixture questions produce truthful snapshot-grounded outcomes; arbitrary questions are explained as unsupported by the preview fixtures rather than given invented live answers. Do not supply or invoke production OpenAI credentials. Isolate preview users, operational records and budget from production, and enable appropriate Vercel preview protection. A controlled preview is a UI/workflow verification environment, not proof of live model accuracy. Live smoke evaluation is separate and explicit.
- **Browser contract:** Preserve typed natural-language outcomes and the existing safe Markdown/table/loading/error presentation. Authentication and admission failures return friendly errors without tables or private fields. Every question-capable route enforces the same server controls. Public client configuration contains only approved public authentication settings; OpenAI keys, private Clerk credentials, PostgreSQL credentials, pricing internals and private records do not appear in assets or response payloads.
- **Build and publication:** Run automated Go/HTTP/state tests and browser asset checks before a deployment can be published. Provision test databases/controlled dependencies without production secrets or paid model calls. A failing test or build prevents promotion and leaves the active production version unchanged. Configure GitHub main as the production branch, protect other-branch previews, and make successful main deployments automatic. The gate must affect the actual deployment path, not merely report a parallel CI failure after production has already changed.
- **Domain and accounts:** Attach only baseball.jamesteuscher.click to the production project, apply the exact DNS/verification records returned for that project, and verify HTTPS and sign-in redirects. Existing root-domain and other DNS records are preserved. Use free Vercel, Clerk and Neon plans with upgrades disabled. Account authentication, private key entry and DNS ownership actions use secure owner-controlled mechanisms, without values appearing in chat or captured output.

## Testing Decisions

- **Confirmed primary seam:** Reuse public HTTP requests/responses as the main test boundary already agreed for this application. Hosted scenarios add real PostgreSQL operational fixtures and controlled authentication/provider transports behind that same boundary. Continue real SQLite and independently checked batting reference values. Test the resulting user behavior; do not assert helper call order, exact generated SQL, internal object shapes or private row layouts.
- **Authentication:** Exercise actual supported verification against deterministic issuer/key/session/user fixtures. Unauthenticated, expired, wrong-issuer and uninvited/removed users reach no model request. Confirm that a browser claiming an approved email cannot override verified identity. Cover sign-in/out and safe access errors through focused browser checks.
- **Shared confirmations:** Use two independently composed server instances sharing PostgreSQL. Begin on one and confirm/revise on the other; verify correct player/season behavior, user binding, original-question binding, fifteen-minute expiry and one-use behavior under concurrent consumes. Verify database outages fail closed and no general history is retained.
- **Admission:** Use controlled time and concurrent public requests to verify the first twenty logical questions are admitted, the twenty-first is denied, the rolling window restores access, valid confirmation/revision does not double count, and one user’s simultaneous requests cannot both run. Cover lease crash recovery and stale-release protection without long real waits.
- **Spending:** Drive public questions through the real model-call module and controlled provider responses. Verify no provider call starts before committed reservation, concurrent instances cannot exceed $10, comparison/correction/answer calls are all counted, insufficient balance denies the next call, and month rollover occurs at UTC midnight. Inspect provider request bounds and declared tier through the controlled transport rather than invoking paid inference. Known usage permits safe settlement; uncertain failures, timeout and ledger outage never generate a refund-based bypass. Test money rounding and boundary cases through public outcomes and observable provider requests, with fixture/artifact checks where needed to independently verify state totals.
- **Deadlines and failures:** Use controlled cancellation/timing at the HTTP seam to cover the complete two-minute request budget, existing ten-second SQL limit, exhausted correction, failed summaries, interrupted model work and independent comparison outcomes. Avoid two-minute sleeps in ordinary tests. Verify the browser keeps the previous result and stops the animation on denial or timeout.
- **Previews and privacy:** Exercise preview composition through public HTTP and focused browser checks. Production provider endpoints are never contacted even if an unexpected key exists in the environment. Separate state prevents preview activity from consuming production allowances or creating production approvals. Inspect responses/assets/log captures for private keys, connection/auth material, full histories and SQL/schema leakage. Hosted record generation remains disabled.
- **Deployment artifacts:** Treat clean-checkout snapshot generation, Go hosted startup, explicit asset bundling, environment validation and test/build promotion gating as deployment artifact checks alongside HTTP tests, rather than new application testing interfaces. Verify the imported season counts/metrics and that private database files are unavailable as assets.
- **Deployment smoke checks:** Verify a protected preview first, then HTTPS/sign-in/access denial and an authorized question on the custom subdomain. Paid production smoke requests require secure owner-provided credentials and must pass the production allowance guard. Report what was actually verified; do not claim an unperformed cloud deployment, DNS change, email delivery or live accuracy evaluation.
- **Prior art:** The repository already has public HTTP tests with real SQLite, controlled Model implementations and local OpenAI SDK providers; held-out ranking fixtures; confirmation/concurrency/correction/result-limit/privacy tests; browser asset/CSP tests; and native browser checks for Markdown, animation and retained answers. Extend these patterns rather than replacing the project or introducing a broad new frontend framework.

## Out of Scope

- Real MCP protocol support, another language/framework rewrite, live MLB fetching, dataset writes through natural-language requests, team/AL/NL subdivisions, or general multi-turn conversation memory.
- Paid hosting/authentication/database subscriptions, automatic paid upgrades, paid Clerk Allowlist/bans, AI Gateway routing/BYOK/fallbacks, or budget overrides.
- A new in-browser administration console; invitation/access management stays in Clerk’s dashboard and infrastructure configuration stays with the owner.
- Persistent hosted evaluation histories or full request/answer audit archives.
- A spending guarantee over the owner’s entire provider account, other applications, unrelated keys, taxes/fees or future rate changes. The application guard admits calls only under validated cost assumptions.
- Moving or replacing the root domain’s site, transferring registration or changing unrelated DNS records.

Free quota exhaustion is a service-unavailable condition, not permission to purchase a subscription or bypass controls.

Neon’s free transactional state storage is suitable for the small operational data set: [plans](https://neon.com/docs/introduction/plans). PostgreSQL supports transactional row locking: [locking](https://www.postgresql.org/docs/current/explicit-locking.html).
- Budget profiles must cover complete inputs, reasoning/output tokens and the maximum applicable cache category; provider budget alerts alone are not enforcement. Source documentation: [model](https://developers.openai.com/api/docs/models/gpt-6.1-sol), [pricing](https://developers.openai.com/api/docs/pricing), [token counting](https://developers.openai.com/api/docs/guides/token-counting). Avoid using a counting endpoint with uncertain charges as an unaccounted budget bypass.
